# 分轮需求确认

先用盘点结果减少问题。下面是语义模板，不是绑定某个工具的 JSON schema。每轮通常 1–3 个问题；单选工具无法多选时拆题或接受用户文字列表。不要把选择默认项当作回答。

## 第一轮：工作范围

开场示例：“检测到 arm64 macOS、已安装 Homebrew、Node 由 nvm 管理。默认保留这些环境，只补缺。”

| 主题 | 可提供的选择 | 目的 |
|---|---|---|
| 本次动作 | 盘点并给建议 / 按选择配置 / 继续上次配置 | 区分检查与实际写入 |
| 工作需求 | Web/Node / Python / Apple 原生开发 / 通用终端 / 自定义组合 | 决定语言环境，不强加全套 |
| 已有环境策略 | 保留可用环境、只补缺（建议） / 逐项讨论迁移 | 防止包管理器和默认版本被替换 |

用户明确要求“直接按已有选择配置”时，复用选择，不再次完整问卷。

## 第二轮：选择组件

根据第一轮逐组询问：

- AI CLI：Claude、Codex、Kimi、Grok、Cursor Agent、Gemini，可多选或全跳过。traex 标注“公开来源未确认；需你提供官方项目/分发入口”，不让这个缺口阻塞其他组件。
- 实用工具：后台删除、yazi、glow、ripgrep；搜索增强 fd/fzf/zoxide 单独说明作用。
- 可选媒体：radio-active、spotatui。说明 spotatui macOS 音源限制，先问需要 Spotify 还是其他来源，不承诺全部可用。
- 可选外部服务：surge、PicGo。安装不等于发布/上传授权；账户和秘密让用户自行输入。
- shell 集成：只加载所选实用函数，还是额外开启 yazi 的 `y`、fzf 快捷键、zoxide 的 `z`。检测已有同名功能时给差异而非覆盖。
- 开发环境：已有 Node/Python 管理器继续使用；缺失时按仓库建议安装。问项目需要的版本，不把最新版本等同于兼容版本。

## 第三轮：仅对冲突和维护提问

具体说明发现的冲突，如：“codex 在 npm 和 Homebrew 都有安装，目前 PATH 使用 npm；保留 npm，还是审阅迁移到 Homebrew 的计划？”不要问没有发现的冲突。

升级默认手动。只有用户选择定时升级时，再确认：哪些工具、允许稳定版更新还是锁版本、每日/每周、本地时间、日志保留、非交互更新不支持时跳过。不能默认套用附件里的 09:53 和个人 launchd label。

## 执行前的具体确认

展示将新增的工具和依赖、已有环境的保留项、要改的文件及备份位置、需要迁移/登录/定时权限的项。提问示例：“本次会新增 glow 和后台删除函数，只在现有 zshrc 追加一个加载块；Node 与其他 CLI 不动。按这个计划执行吗？”

这轮应是对具体计划的确认，不是空泛的“允许我操作你的电脑吗”。若已有明确授权，省略重复确认。计划范围内逐项继续，只有新增风险或范围变化再问。

## 用户无回复 / 工具不可用

可以完成只读盘点、来源核验和变更草案；暂停尚未授权的写入。普通对话是可用回退，不把缺少 `AskUserQuestions` 视为全部失败。不要自动选择所有组件或依赖。
