# setup-mac

在仓库根目录读取 `AGENTS.md`、`docs/guides/workflow.md` 与 `docs/guides/selection-and-conflicts.md`。这是给 agent 的配置链路，不执行全量安装器。用户已明确的范围、排除、版本和“不再询问”直接复用，不重跑问卷。

## 盘点和选择

先确认目标是用户要配置的 Mac，进行最少只读盘点：架构、系统、shell/真实配置入口、包管理器/解释器与已有渠道。已有 `.local/` 报告先核对现状再续做，不重复安装。

读取 `docs/README.md` 及五个分类 README：`base`、`ai-tools`、`scripts`、`cli-tools`、`gui-apps`。它们是工具列表唯一来源。**按分类向用户展示每个工具的名称和关键区别**，可附当前已装/缺失状态；不能只显示“基础/AI/GUI”标签就声称用户已知具体全选范围。

按 [问题模板](references/questions.md) 使用实际可用的 `AskUserQuestions`；宿主叫 `AskUserQuestion` 或其他名称时使用真实工具和 schema。尊重题数、多选、当前模式及权限限制。无可用工具则普通对话；不虚构工具、不为提问安装 MCP。

允许直接选择“一键全选并自动处理冲突”，也支持分类、全选但询问冲突、白名单与黑名单组合。白名单默认 strict，黑名单优先，冲突默认 ask；用户选 auto 后由 agent 决定保留/合并/补装/跳过，不能因普通配置冲突停下来再问。具体依赖、消歧、无回复和外部操作边界遵循共享规则。

## 形成具体计划并执行

规范化并记录动作、清单快照、名单、冲突/依赖策略和附加偏好。只读取所选工具的独立文档及必要依赖文档；来源规则在 `docs/guides/sources.md`。清单来自当前用户仓库，包含后来通过 add-config 收录的条目，不固定工具数量；标为“待核验”的条目可展示和继续核验，但核验完成前不执行其安装命令。

展示每项当前来源/版本、保留/新增/修复/跳过、依据、文件改动、依赖、备份与回滚、待账号操作。已有“安装这些”或“一键全选自动处理”的明确指令就继续，不附加重复确认。只给建议的请求不进行环境写入；未授权的新范围按 ask/auto 规则询问或跳过。

安装前重新核验上游身份、包名、平台和依赖。先处理基础/运行时，再处理依赖它们的 CLI 与 App。命令失败只影响关联项；修复 shell 时定位真实入口、先备份、只合并必要差异、确保幂等。auto 要实际完成可安全解决的冲突，不能一律跳过。

已有环境保持可用，Node 的 system/nvm 精确版本与最终入口分别验收，pyenv/uv 的解释器职责按单工具页协调。定时升级、默认 App、登录启动等未选就不开启。工具安装不授权删除缓存、发布/上传文件或付费推理；系统/账户审批不能通过问卷替代。

## 验证和交接

执行 `docs/guides/validation.md` 对应验收，按 `templates/setup-report.md` 记录到 `.local/`。至少确认所选工具的渠道、版本与新 shell 的来源；GUI、认证、真实功能没有实测就分开标记。验证后台删除只用自建临时目标；修改其实现时必须运行含真实 PTY 的测试。

最终区分新增、保留、修复、跳过、失败、待用户操作，列出自动冲突决定、未满足目标与回滚位置。不将机器报告、日志、账号信息或凭据提交 Git。
