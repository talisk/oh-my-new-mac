# 验证与交接标准

## 仓库本身

在仓库根目录执行：

```sh
zsh -n utilities/rm-async/functions.zsh
zsh -n utilities/rm-async/worker.zsh
python3 -m unittest discover -s tests -v
git diff --check
```

测试使用 Python 标准库、macOS 自带 zsh 和系统工具，不装额外依赖。测试目录在被忽略的 `.local/`；只删除测试自己创建的目标，不修改 HOME 或真实 shell 配置。非 macOS 会跳过运行测试，不能把跳过当作通过。

覆盖多目标/空格/末尾换行、符号链接、单目标 ID 兼容、无效参数整批预检、umask 保持、根目录/主目录/当前目录/状态目录保护、目标替换拒绝、暂停及 PID 复用识别。PTY 用例创建真实控制终端、后台提交并退出启动 shell，确认任务结束；这覆盖曾经出现的 queued 假进展问题。

还应检查所有相对文档链接、agent 入口符号链接、Gemini TOML、plist 示例和 skill frontmatter。若宿主提供 skill-creator 的验证器，可使用；本仓库不把它当成所有 agent 必装依赖。

## 每台机器的配置验收

| 层级 | 证据 | 不能据此宣称 |
|---|---|---|
| 源码/语法 | shell 语法、plist/TOML 可解析 | 实际已安装或可运行 |
| 安装 | 明确渠道安装退出码、包记录、版本 | 当前 PATH 一定使用这套版本 |
| shell | 新交互式/登录 shell 中的来源、版本和所选初始化 | TUI/认证/服务功能完整可用 |
| 实际功能 | 用户要求范围内的操作结果 | 未操作过的其他功能成功 |
| 认证 | 用户完成官方登录后的非敏感状态 | 账号一定有额度、Premium 或付费授权 |
| 定时维护 | 已加载任务、实际执行结果与日志 | 未来每次都准时成功 |

媒体播放、网页登录、GUI、发布、上传和收费请求不能为了验收而擅自触发。安装后尚未获得这类操作授权，就报告“CLI 安装/PATH 已验证，认证/播放/上传待用户完成”。

## 配置链路的行为验收场景

以下是维护者检查 skill 决策的场景，不是假称已在所有 agent/新 Mac 中执行通过的自动化测试。验收时按用户请求与盘点结果推导目标集合、动作和待办，不只检查是否出现某个关键词。

| 用户请求与现状 | 应观察到的行为 |
|---|---|
| 新 Mac：“全选，冲突自己解决” | 展示五类具体工具后展开 40 项及必要依赖；不逐项再问，不默认开定时/永久唤醒；受限组件单独跳过 |
| “全选”，Codex npm/Brew 双装 | 默认 ask，集中提出实际渠道冲突；不默认改成 auto 或升级所有全局包 |
| “只装 rm-async 和 glow，别问”，没有 Brew | rm-async 可用系统工具完成；glow 选择已核实且不越范围的渠道，否则记缺依赖；不暗装 Brew |
| “只装 yazi，允许必要依赖，不装 ffmpeg” | 不把可选预览器 FFmpeg 加入；若当期配方强制依赖排除项，则换合规渠道或跳过 yazi |
| “基础和 AI，不要 Gemini、grok” | 仅展开两类减去 gemini/grok，未选 GUI 不处理；黑名单不触发卸载已有工具 |
| “只装 Cursor，冲突别问”，无上下文 | 不擅自扩成 CLI+Desktop；将歧义项记录跳过，其他确定项可继续 |
| system Node 合适，nvm 版本不同，auto | 安装同一个精确版本并设所选默认入口；不卸载系统 Node 或搬走所有旧全局 npm 包 |
| system Node 过旧，其他 App 依赖它 | 保留旧依赖，为所选工具配置兼容入口，报告未完全统一，不声称两套数字一致 |
| pyenv 与原有 uv-managed 项目共存 | 本次组合可指定 pyenv 解释器，但不全局禁止旧项目所需的 uv 解释器 |
| Caffeine 为 Domzilla 版，全选 auto | 保留原发行方，不用 Brew IntelliScape 版覆盖；两个防休眠 App 不同时自动启用 |
| Codex Desktop 当期无匹配受支持分发 / App Store 未登录 | 不安装同名假包或未经选择的替代产品，标待来源/用户操作，继续其他项 |
| 再跑上次相同范围 | 核对实际状态后复用选择，不重复插入 source、重装包、创建同名定时任务 |

## 本次仓库交付的边界

2026-08-31 本机 macOS 验证：5 项 unittest 全部通过（包含真实 PTY），zsh 语法、skill-creator 校验、Gemini TOML、plist 示例、相对链接与入口链接均通过；两份原始附件按字节比对一致。

来源方法见 [sources.md](sources.md)，每个工具页保存各自依据与分发限制。原附件中的未知来源工具仅保留在归档，不进入全选清单。
