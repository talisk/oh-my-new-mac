# 后台永久删除：rm_async / rm_progress

实现位于 [functions.zsh](../utilities/rm-async/functions.zsh) 和 [worker.zsh](../utilities/rm-async/worker.zsh)。仅支持 macOS zsh，使用系统内置工具，无须 pip/npm/Homebrew 依赖。

**不经过废纸篓，删除不可恢复。** 配置流程只安装命令，不删除真实文件；测试只用临时目录。

## 使用

```zsh
rm_async "/需要删除的目录一" "/含 空格的目录二"
```

一次传多个路径，先统一检查参数；每个目标创建一个后台任务，输出 `job.XXXXXXXX` 与转义后的目标路径。单目标只输出 ID，兼容 `id=$(rm_async "路径")`。文件、目录、符号链接均可作为目标；不沿最终符号链接删除其指向的目录。

```zsh
rm_progress job.XXXXXXXX
```

| 状态 | 含义 |
|---|---|
| `queued` | 已创建任务，worker 尚未进入统计；长时间不变需检查进程 |
| `scanning` | 后台 `du` 统计初始磁盘占用，尚未开始删除 |
| `deleting` | 已进入 `rm -rf`；查询时按剩余占用估算进度 |
| `succeeded` | 删除命令退出码为 0；显示 100% |
| `failed` | worker 返回非零，展示日志位置和末尾信息 |
| `stopped` | 进程被系统/作业控制暂停，不能认定有进展 |
| `interrupted` | worker 不在、PID 被其他程序复用或未留下结果；不自动重启删除 |

统计与删除都在后台；查询 `deleting` 状态时会现场运行只读 `du`，目录很大时查询会慢。百分比是磁盘占用估算，不是文件数或 rm 内置进度。100% 只在结果成功后显示；扫描失败时仍可删除，但可能无法提供百分比。

后台任务可跨启动 shell 的退出继续运行，不跨重启恢复。机器睡眠、磁盘/权限问题仍可能暂停进展。退出码 0 只表示本次 rm 成功，不保证其他应用之后不重建同名缓存，也不等于 APFS 立即释放同量物理空间。

## 安装方法（由 agent 按需求执行）

1. 检查用户是否使用 zsh、真实 `ZDOTDIR`、现有同名函数及 `~/.config/rm-async/`。若已有本功能，比较版本并检查活跃任务；不要截断正在执行的 worker，也不要丢弃旧任务状态。
2. 用户选择后备份将修改的文件，将两个实现文件复制到 `~/.config/rm-async/`。使用同目录临时文件和原子替换，不把整个仓库的配置灌进主目录。两个文件需一起部署；worker 路径从函数定义文件旁解析。
3. 只在实际的 zsh 配置入口合并一次 [工作流中的加载块](workflow.md#最小修改)。已有同等 source 时不重复追加；旧 `rm-async` 标记先识别后合并。
4. 当前用户终端执行 `source ~/.config/rm-async/functions.zsh`，或打开新终端。agent 子进程里的 source 不会改变用户已打开的 shell。
5. 用临时目录验证单目标、多目标、空格、符号链接、返回 ID、查询和终端退出后继续运行。没有 PTY 就明确未覆盖真实作业控制。

默认状态目录 `~/.local/state/rm-async/`，每个 job 私有目录保存 NUL 结尾的目标路径、PID、阶段、初始大小、日志、退出码以及目标设备/inode。`RM_ASYNC_STATE_DIR` 可选覆盖状态目录（例如仓库测试）；启动和查询必须使用同一个值。它不是安装器开关。

## 安全边界与已修复问题

- 拒绝空参数、根目录、主目录/当前目录及其祖先，也保护 worker 与状态目录的祖先。所有显然无效的输入会在启动任何删除前拒绝；但启动期间的磁盘错误并不提供“整批事务”保证。
- 不支持任意 rm 选项；可用 `--` 终止选项语义，带空格的路径必须引用。不要传同一目录及其子目录来并发删除，也不要在任务执行期间重命名、替换目标或让应用继续写入。
- 提交时保存设备/inode，扫描前后检查目标是否仍是同一个对象；发现替换返回失败，避免明显误删。此检查**不是文件系统锁或无竞态安全边界**，无法完全消除检查和 rm 之间的替换竞态，也不能阻止恶意并发改写祖先符号链接。适用于由用户控制且已停止写入的普通目录。
- 早期实现用 zsh `read -d ''` 读取路径，会在交互终端后台任务中触碰 TTY 设置而被暂停。当前使用保留 NUL 哨兵的 zsh 文件读取方式，避免该终端操作，也保留路径末尾换行。
- 旧版仅凭 `kill -0` 误把暂停/复用的 PID 当作活动任务；当前还检查进程状态和命令身份。PID 校验仍是尽力检测，不是持久进程句柄。
- 不自动发送 `CONT`、杀进程或重新提交失败/中断任务。恢复前先核对准确任务、进程树与目标，并获得对应删除授权；无需为单纯查询权限提问。

## 回滚

移除本次新增的加载块后，新 shell 不再加载函数；这不会中止已经启动的删除。活跃任务结束前保留 worker、日志和状态。只有明确选择卸载后再移除工具文件；不要把清空状态目录当作“取消删除”。
